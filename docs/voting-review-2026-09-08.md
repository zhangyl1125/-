# 投票规则核查（2026-09-08）

范围：按用户确认，本次核查现有点赞/撤票规则；《Yining/规则0908/规则.md》中的审核、阶段和入围全流程仅列缺项，不在本次实现。

## 已实现的规则

| 规则 | 实现与核查依据 |
| --- | --- |
| 每人每赛道最多4票，不要求投满 | `VoteIdeaUseCase.execute` 读取 `app.voting.max-votes-per-track`，默认4；新增第五票拒绝，撤票不受上限拦截 |
| 各赛道、各评选独立计票 | 先按用户与评选查询选票，再按规范化赛道过滤 |
| 每次增删后跨部门票至少50% | 校验最终选票集合，`ownVotes * 2 > resultingTotal` 则拒绝；总票1/2/3/4分别至少跨部门1/1/2/2票 |
| 每位候选人最多1票 | 再次点击切换为撤票；数据库 `idea_votes` 具有 `(idea_id,user_id)` 唯一约束 |
| 名册、部门来源 | 账号须唯一匹配BD名册；使用候选人而非代报名人的真实部门，Org.code取“-”前部分；无法确认部门时拒绝 |
| 并发约束 | 事务内获取案例锁和投票用户行锁，再读取选票并校验；同一用户跨候选人的增删串行处理 |
| 撤票与重选 | 撤跨部门票如破坏比例则拒绝，应先撤本部门票；另有按评选、赛道清空本人选票接口 |
| 失败时保留状态 | 前端只在API成功后变更点赞状态；购物车与卡片使用同一份状态，失败显示规则提示 |

不能把“至少50%”理解成任何情况下都要投两张跨部门票，也不能把“最多4票”理解为必须投满。当前规则允许全部票投给跨部门候选人。没有独立的“禁止投自己”规则；自己属于同部门，受50%比例约束。

## 相对规则0908文档的缺项（本次未实现）

1. **审核门槛**：点赞用例没有检查经理审核通过状态；当前模型没有完整审核/退回/重提状态机。不能声称只有审核通过的候选人能投。
2. **投票阶段锁定**：点赞和清空选票接口没有校验 `associate-voting` 阶段，也没有按时间线自动锁定；目前页面展示的日期不是后端生效条件。关闭活动后仍需后端阶段门槛才能可靠禁止增删。
3. **入围快照**：没有每赛道前30名及第30名同票全部入围的不可变快照；前端仍保留旧的10人入围/5人决赛常量，不能作为新规则依据。
4. **票数可见性**：员工候选人卡片和接口仍有实时总票数，尚未只显示本人是否投票。
5. **委员会范围**：当前有指定评委和加权评分实现，但未基于入围快照限制仅对入围人评分，阶段结束锁分也未实现。
6. **票篮统计**：本次实现非模态面板、即时增删及总数同步；每赛道已选/剩余额度、个人跨部门比例汇总尚未实现。
7. **特殊票数调整**：新文档的超级管理员审计加票、反向撤销与评分代改审计未包含在当前点赞系统内。

此外，后端票数上限可配置，前端说明目前固定为4票。部署若修改 `app.voting.max-votes-per-track`，需同步前端说明，或增加统一读取规则配置的接口。
